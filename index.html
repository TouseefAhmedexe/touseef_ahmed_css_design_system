Bloomrix UI

A small CSS design system and component library. It is written in SCSS, compiled to one CSS file, and themed with CSS custom properties.

<link rel="stylesheet" href="dist/bloomrix-ui.css">

<button class="btn btn--primary" type="button">Save</button>

Naming conventions

Pattern Example Meaning
Block .card A component that stands on its own
Element .card__title A part of a block
Modifier .btn--primary, .field--error A variation or a state of a block
Layout primitive .stack, .cluster, .grid-auto, .cq Spacing and layout helpers with no look of their own
Utility .u-mt-4, .u-bg-primary One job, usable on any element

Cascade layers

The layers are declared in this order. A later layer always wins over an earlier one, whatever the selector.

  1. reset: removes browser defaults
  2. tokens: spacing, type, radius and width values
  3. themes: color and shadow values for light and dark
  4. base: typography and element styles
  5. layout: containers and layout primitives
  6. components: buttons, forms, cards and the rest
  7. utilities: small helper classes
  8. overrides: reduced motion

Themes

Every color comes from a CSS custom property. The light values are set on :root. The dark values are used when data-theme="dark" is set on an element, or when the device prefers a dark scheme and no theme has been chosen.

Because the tokens are set on any element that has data-theme, one part of a page can use a different theme from the rest. The two panels below use the same markup.

Switching themes

  • The buttons in the header switch the whole page. The choice is saved in localStorage.
  • When nothing is saved, the page follows your device through prefers-color-scheme.
  • Use device theme removes the saved choice.

Change a token while the page runs

Custom properties are read by the browser, so changing one value updates everything that uses it. This changes only --color-primary. The hover color and the text color on buttons do not change, so check the contrast yourself.

Tooltips and modal

Tooltips

Hover or focus me A tooltip below

The tooltip text is a hint. Do not put information there that a person must read. Near the edge of a small window, a long tooltip can be cut off.

Modal

The modal uses the native <dialog> element. Press Escape, click the dark area or use a button to close it.

<dialog class="modal" id="demo-modal" aria-labelledby="demo-modal-title">
    <form method="dialog">
        <div class="modal__header"><h3 class="modal__title" id="demo-modal-title">Title</h3></div>
        <div class="modal__body"><p>Content</p></div>
        <div class="modal__footer"><button class="btn btn--primary">Close</button></div>
    </form>
</dialog>

Responsive behavior

Components respond to the space they are placed in. Page layout responds to the window.

Use this When Examples here
Container query (@container) A component can sit in a wide or a narrow place, such as a main column, a sidebar or a grid cell Profile, statistics and pricing cards
Media query (@media) The decision depends on the window or the device: page layout, navigation, and user preferences The documentation sidebar, prefers-color-scheme, prefers-reduced-motion
clamp() A size should grow smoothly between two limits Headings and the big card numbers

Resize a container

On a desktop browser, drag the bottom-right corner of the dashed box. The card changes layout at 28rem of container width, and the window does not change.
